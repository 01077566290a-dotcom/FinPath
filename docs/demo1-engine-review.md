# 데모1 엔진 점검

## 이번 범위

화면 목표는 **자연어 입력 화면 → 해석 결과 확인 및 후속 정보 수집 화면**이다. 이번 작업에서는 해당 화면 전환을 구현하지 않고, 기존 1·2단계 데이터·엔진만 보완했다. 규칙 기반 데모이며 AI API나 신규 타임라인 기능은 추가하지 않았다.

독립 서브 에이전트가 읽기 전용으로 실패 문장을 재현하고, 기존 해석기·상태·질문 제약과 작은 회귀 데이터셋만 보완하는 범위를 검토했다.

## 재현 및 수정

| 입력 | 이전 문제 | 수정 정책 |
| --- | --- | --- |
| 이번 달 첫 월급 260만원 받았어요 | 예정 상태와 이미 받음 슬롯 공존 | 명시적 수령 표현을 단순 시기 표현보다 우선 |
| 취업했는데 다음 달 독립할 예정 | 취업까지 예정으로 분류 | 접속절 분리 보강 |
| 월급은 260만원이고 대출은 안 받을 거예요 | 월급까지 해당 없음 | 부정 표현의 절 범위 분리 |
| 매달 50만원 저축 | 현재 저축액으로 오인 | 보유액을 단정하지 않고 질문 |
| 입사 13년 / 12개월 차 | 1~3년 / 1년 미만 부분매칭 오류 | 숫자 전체를 파싱하고 3년 초과 선택지 추가 |
| 월급 250~350만원 | 350만원만 확정 | 범위 표현은 null로 남기고 질문 |
| 월급 260만 받고 있어요 | 금액 누락 | 원 생략 표현 지원 |
| 내년 2월 독립 | 무조건 12개월로 계산 | 달력 날짜는 이번 버전에서 추정하지 않고 질문 |

현재 상태에 맞는 입사·월급 시기 선택지만 질문과 정보 수정에 표시하며, 상태 함수에서도 모순된 선택을 거부한다. 해석기 반환 계약은 유지하고 입사 시기 enum에 `gt3y` 하나만 추가했다.

## 이벤트 커버리지

현재 지원하는 5개 이벤트는 취업·월급·독립·주거계약·대출이다. 다음 후보를 이미 지원한다고 표시하지 않는다.

| 후보 | 추가 전에 정할 내용 |
| --- | --- |
| 퇴사·실직 | 취업의 no와 별개 사건으로 관리할지, 소득 중단·생활비 정보를 어떻게 받을지 |
| 이직 | 첫 취업과 같은 규칙인지, 기존 직장·새 직장 시점을 분리할지 |
| 비상자금·목돈 목표 | 월 저축 흐름과 현재 보유액, 목표액·기한을 어떻게 구분할지 |
| 계약 갱신·대출 상환 | 신규 계약·신규 대출과 다른 필요 정보 및 종료 상태 |

이벤트는 키워드만 붙여 추가하지 않고, 의미·상태·필요 슬롯·질문·예시를 한 묶음으로 정의한 뒤 확장한다. 예컨대 ‘퇴사했어요’는 현재 의도적으로 미인식으로 남기며 잘못된 취업 yes를 생성하지 않는다.

## 다음 평가 방식과 한계

`tests/fixtures/language-cases.js`에 실제 실패 문장과 기대 이벤트·슬롯을 추가하고 `npm test`로 확인한다. 고정 회귀 데이터의 통과는 일반 한국어 정확도 측정치가 아니다. 복잡한 조건·대조, 한 절의 다중 사건, 다중 인물, 정확한 달력 날짜, 같은 슬롯의 서로 다른 시점은 아직 보장하지 않는다. 이러한 확장을 위해 새로운 프레임워크나 신뢰도 점수 체계는 추가하지 않았다.
