# 사용자 피드백 반영

- 금액: 만 원 단위 소수와 원·만·억 표기를 함께 해석한다. `250.5만 원`은 250.5, `1억`은 10000이다. 기간은 정수 검증을 유지한다. 목표 금액 상한은 기존 10000000만 원이며 빠른 선택에 1억을 추가했다.
- 목표: 목적별 필요 자금을 먼저 배정하고 입력한 목돈 목표의 남은 금액을 추가 목표로 시뮬레이션한다. 보유 자산은 시뮬레이터가 한 번만 배정한다.
- 생활비: 현재 월세·관리비를 새 주거비로 대체하고 지역 이동에 따른 생활비 증가분을 직접 입력한다. 지역별 시세 데이터가 없으므로 자동 지역 물가 보정은 아직 하지 않는다.
- 대출: 새 주거 대출의 월 원금 상환액을 입력받아 추정 이자와 함께 지출에 반영한다. 원금 미정은 보고서에 표시한다. 잔액에 따른 이자 감소·원금 완납 후 지출 해제·만기 일시상환 스케줄은 아직 구현하지 않았다.
- 공유: 기본 링크에는 목표 종류만 담는다. 금액·지역·나이는 포함하지 않는다. 전체 공개는 별도 체크를 요구한다. 기존 링크에 포함된 개인정보는 소급 제거할 수 없다.
- 정책: 구조화된 소득 상한과 접수 기간이 있는 데이터는 조건 불충족·접수 전·접수 종료를 구분한다. 없는 데이터는 추가 확인 필요로 표시한다. 보조금24 신청기한을 보존하고 공식 공고 URL이 있으면 우선 사용한다. 기존 수동 정책 목록의 최신 공고·소득 기준·접수 기간 검증과 가구소득 입력은 후속 작업이다. 세후 월급을 세전 심사 소득으로 환산하지 않는다.

회귀 검증: `npm.cmd test`, 프로덕션 검증: `npm.cmd run build`.

## 이어서 보완한 것 (Claude Code)

- 휴대폰 키패드의 쉼표 소수점(`250,5`)도 250.5로 읽는다. 천 단위 쉼표(`2,505`, `1,000,000`)는 그대로.
- 입력은 소수를 받되 결과 화면(리포트·타임라인·요약)의 금액은 만 원 단위 정수로 보여 준다. 내가 입력한 답을 다시 보여 주는 곳만 소수 그대로. 목표 금액(비상자금·권장 추가분·목돈 목표)은 만 원 단위 정수로 맞춘다.
- 목돈 목표가 타임라인 단계("목돈 ○○ 모으기")로도 보인다.
- 목돈 목표 기한이 입주보다 늦으면 리포트의 기준 기한을 목돈 목표 기한으로 잡는다 ("3월 전에 다 모아요 — 4월이면 끝나요" 같은 모순 제거). 해결책 문구도 그 경우 '목표 시점'으로.
- 정책 카드: 원래 조건 설명은 그대로 두고, 신청 가능 여부는 짧은 표시("추가 확인 필요" 등)로 붙인다.
- 공유: 시연 인물은 가상 인물이라 전체 공유, 금액을 가린 링크를 받은 화면을 카드 모양으로 정리.

## 2차 검토 반영 (P1·P2)

- 목표 진단: '기한까지 모을 수 있는 돈'을 독립 전 저축 → 독립 후 저축(대출 완납 뒤엔 원금·이자만큼 더) 순서로 달마다 더해 계산한다. 시뮬레이션과 같은 흐름(`monthlyFlow`)이라 "기한 전에 모아요"와 실제 완료 시점이 어긋나지 않는다.
- 월급·저축을 고치면 '지금 내는 월세' 답을 다시 검증하고, 맞지 않으면 지워서 다시 묻는다.
- 새 주거 대출: 월 원금 상환액이 있으면 `대출 ÷ 원금`개월 뒤 완납으로 보고 그 뒤 매달 원금+이자만큼 더 모인다. 남은 원금에 따른 이자 감소는 아직 반영하지 않는다(보수적 추정).
- 소수 교통비(12.5만 원)를 프로필과 독립 후 지출에 반영한다.
- 남은 일: 정책 자격 판정은 수동 정책 11개에 구조화된 소득 기준·접수 기간이 없고 사용자 세전 소득도 묻지 않아 '추가 확인 필요' 표시 수준이다.
